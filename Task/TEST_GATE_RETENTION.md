# 测试门禁证据保留与迁移规则

## 目标

避免历史 `RUN-*` 证据长期停留在 `tmp/test_lab`，造成每次门禁重复枚举历史对象并持续占用本地磁盘。该规则不降低保护树、运行时 watcher、句柄围栏、活动数据库哈希、进程树或源码见证门禁。

## 目录职责

- `tmp/test_lab/<run_id>`：热目录，只放当前运行和最近一次已验收全绿运行。
- `tmp/test_lab_archives/`：已校验的便携归档与本地 manifest；受 `.gitignore` 保护，不进入 Git。
- 仓库外的本机暂存：仅在执行环境不允许删除时使用；它是可恢复副本，不是规范证据，也不参与迁移。
- `Task/reports/`：进入 Git 的验收摘要、哈希、边界和恢复说明，是跨电脑恢复的规范状态。

## 触发条件

满足任一条件即整理：

1. 一个 M0—M5 验收切片形成终态；
2. `tmp/test_lab` 累计 10 个已完成运行；
3. `tmp/test_lab` 逻辑大小达到 1 GiB；
4. 所在卷可用空间低于当前门禁预算。

## 整理顺序

1. 确认没有活动 safe launcher、pytest、业务 mutation 或未释放 writer lease。
2. 只选择已结束且不再写入的运行目录；最新验收全绿运行保留在热目录。
3. 拒绝 Reparse、绝对成员、盘符成员和含 `..` 的归档成员。
4. 生成相对路径 `tar.gz`，完整执行成员清单解压校验并记录 SHA-256、字节数、成员数和顶层运行数。
5. 证明归档覆盖与待迁出运行集合完全相等后，才允许移动或删除热目录历史。
6. 删除受执行环境限制时，移动到仓库外的本机可恢复暂存；不得改用另一种 shell 绕过限制。
7. 整理后复核最新全绿 `run-result.json`、活动 SQLite 哈希、归档哈希、热目录集合和卷可用空间。

safe launcher 不自动归档或清理历史。归档属于验收后的维护动作，不能与正在受保护的测试运行并发。

## 保留策略

- 热目录：最近一次已验收全绿运行。
- 失败运行：保留到其原因、替代轮次和安全门状态写入报告并进入已校验归档。
- 原始逐文件历史：由归档保存；不要求在热目录重复保留。
- Git：只保存报告、状态、清单和提交历史，不保存本地实验树或归档二进制。

## 跨电脑迁移

正常源码迁移只需要 Git 仓库和按 `requirements.txt` 重建的虚拟环境；`.venv`、仓库外本机暂存和旧物理路径都不是交付物。

若需要完整取证历史，另行复制 `tmp/test_lab_archives/`，在新电脑先核对 `archive-manifest.json` 中的 SHA-256，再解压到新的空目录。禁止把归档直接覆盖到活动 `tmp/test_lab`。

只读复核示例：

```powershell
Get-FileHash tmp/test_lab_archives/*.tar.gz -Algorithm SHA256
tar -tzf tmp/test_lab_archives/<archive>.tar.gz
```
