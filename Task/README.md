# M0—M5 长期自动化执行规范

版本：1.1.0
状态：规范性（Normative）
制定日期：2026-07-11
适用根目录：包含受跟踪`.exam-bank-root.json`且通过`app/project_root.py`验证的本机 NTFS 项目根；物理盘符和父目录可随迁移改变

## 1. 本目录的作用

`Task` 是下一次长期自动化工作的唯一核心执行规范集。M0—M5 的设计、实现、测试、审计、阶段推送和最终交付都必须先读取本目录，不得只依据历史聊天、旧质量报告或单个测试结果判断工作完成。

本轮只建立规范，不启动 M0，不处理题库原件，不执行数据库迁移，不生成正式试卷。

## 2. 指令优先级

发生冲突时按以下顺序处理：

1. 用户最新明确要求；
2. 本目录中的安全底线、执行合同和阶段门禁；
3. 仓库根目录的 `AGENTS.md`；
4. `Base/Base.md` 中仍与最新目标兼容的设计资料；
5. 现有代码、历史报告和实现惯例。

历史文件中“首版不做语义搜索、PDF 正式输出”等旧范围，已被用户最新明确要求扩展；历史文件中的本地处理、人工审核、保留原貌和禁止破坏性操作等安全原则继续有效。

## 3. 规范词义

- **必须 / 不得**：硬性要求，自动化任务无权自行放宽。
- **应 / 不应**：默认要求；如需偏离，必须写决策记录并补充风险与验证。
- **可**：满足安全、审计和阶段门禁后允许采用。
- **候选**：尚未通过正式验收，不能标记为可交付。
- **验收通过**：自动测试、真实用户流程、视觉检查、安全审计和恢复验证均满足该阶段要求。

## 4. 不可变底线摘要

1. 项目数据与运行时只有经根标记验证的`PROJECT_ROOT`可写、改、移动或删除；外部参考资料由`Task/local/`中的本机逻辑 ID 映射只读定位。盘符、父目录、cwd、环境变量和调用者参数都不能自行扩大根。仅经依赖审计批准的包管理器事务可按安全规范形成窄系统安装例外。
2. `PROJECT_ROOT`外文件如需转换、裁切、OCR、渲染或其他可能产生副作用的处理，必须先复制至`PROJECT_ROOT\Copy`并登记哈希；只处理副本。
3. 禁止无界递归删除、通配符删除、目录镜像清理、磁盘操作、`git reset --hard`、`git clean`和任何 force push。
4. 原件只增不改；业务删除先进入 Test 内隔离区；正式版本永不被候选版本原地覆盖。
5. 全部业务资料、模型和搜索在本地运行，不上传外部服务；最终断网环境必须跑通完整用户流程。
6. 自动标签只是候选，正式标签必须有人审、证据和版本。
7. “测试通过”不等于“可交付”；每个阶段必须跑真实用户流程，M5 必须以客户可直接使用的成品验收。
8. 发生路径不明、备份失败、数据库损坏、磁盘不足或 Test 外写入迹象时，立即停止相关写操作并保留现场。

## 7. 规范变更

用户允许中途修正非底线规范。变更必须：

1. 说明触发事实，而不是以“实现方便”为理由；
2. 分类为底线、需求、架构、阈值或流程变更；
3. 分析对数据迁移、回滚、阶段门禁和客户体验的影响；
4. 写 ADR，并更新受影响测试和`execution_contract.json`；
5. 不得追溯修改既有验收证据；
6. 底线变更、Test 外写入、远程上传、系统级高风险安装和不可逆数据处理必须请求用户明确决定。

## 8. 开始与结束

下一次长期执行必须从`CURRENT_STATUS.md`和`RUN_STATE.json`恢复，先完成 M0 入场检查，再进入实现。只有 M5 全部门禁通过且生成客户交付包后，才能把长期目标标记完成。
