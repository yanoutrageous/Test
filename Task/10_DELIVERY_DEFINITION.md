# 最终客户交付与完成定义

## 1. 产品身份

V1 面向单机 Windows 环境中的个人试卷整理与命题用户。产品必须完全本地完成：

- 题库浏览、来源追溯和人工复核；
- 结构化、全文和本地语义检索；
- 组卷蓝图与可行性诊断；
- 学生卷、教师卷、答案册、解析册和答题卡生成；
- 原图与 SVG/TikZ 双轨图形；
- 模板编辑、字体校准和视觉回归；
- 完整备份、恢复和重启继续使用。

V1 不得虚假宣称支持：

- 任意扫描件/手机照片无人复核全自动正确导入；
- AI 自动生成可信正式解析；
- 无人工审核的正式标签；
- 云同步、多人协作或账号系统；
- 未获许可的字体、原卷和解析对外分发；
- 当前同卷备份能够抵御整个产品根所在卷损坏。

## 2. 什么才算完成

功能完成必须同时满足：

1. 从正式启动入口可用；
2. 用户无需修改源码、环境变量或数据库；
3. 使用真实代表数据完成主要旅程；
4. 正常、失败、中断和恢复路径通过；
5. 内容、版式、字体和追溯正确；
6. 重启后状态正确；
7. 无产品/项目运行时 Test 外写入和非预期联网；
8. 安装、启动、操作、备份、恢复和故障说明可执行；
9. 代码、依赖、模板、字体和数据版本可追溯；
10. M0—M5 全部门禁在最终发布提交上有效。

以下状态不算完成：

- 只有单元/API/黑盒测试通过；
- 只在开发者调试环境运行；
- 需要手工改数据库才能继续；
- 只用少量合成题演示；
- 只抽查少数 PDF 页；
- 生成了备份但没恢复；
- 更新金标掩盖退化；
- 五类文件存在但彼此不一致；
- 核心流程依赖外网、CDN 或未记录配置；
- 产物和验收报告不对应同一提交/数据版本。

## 3. 客户交付包

建议布局：

```text
release/
├─ launcher/                 # 正式启动、停止和状态入口
├─ app/                      # 应用代码或可运行包
├─ runtime/                  # 许可允许分发的离线依赖
├─ data/                     # 初始化库、迁移和必要本地数据
├─ templates/                # 已批准模板及版本
├─ fonts/                    # 仅许可允许再分发的字体
├─ static/                   # 本地前端、数学渲染等静态资源
├─ docs/
│  ├─ 安装与首次启动.md
│  ├─ 用户操作手册.md
│  ├─ 模板与字体说明.md
│  ├─ 备份与恢复.md
│  ├─ 故障排查.md
│  ├─ 已知限制.md
│  └─ 数据与隐私说明.md
├─ examples/                 # 许可明确且已验收的五类输出样例
├─ qa/
│  ├─ 验收摘要
│  ├─ 需求追踪矩阵
│  ├─ 视觉回归摘要
│  └─ 恢复演练摘要
├─ LICENSES/                 # 第三方许可
├─ SBOM                      # 软件物料清单
└─ release-manifest.json     # 版本、哈希和兼容信息
```

不得包含：

- Git 凭据、token、cookie、浏览器配置；
- 姓名、学号、IP、QQ 等个人信息；
- Test 外绝对路径；
- 临时、缓存、失败导出和未审核内容；
- 未确认分发许可的字体、原卷、解析和模型；
- 开发者专用快捷脚本作为唯一启动方式。

## 4. 便携与本地运行

开发验收与客户版本统一采用“经根标记验证的产品根目录即唯一写根”模型。产品可以整体迁移到另一台 Windows 电脑、另一盘符或另一普通父目录；物理路径不得写死在代码、业务数据库、备份或客户文档中。默认不依赖写入桌面、注册表、AppData 或系统目录。

迁移不是简单修改配置：必须在静止状态完整复制产品根，在新位置验证 marker、本地 NTFS、无 Reparse、依赖、数据库完整性、相对路径引用和空间，再使用新 run ID 执行保护树与固定用户流程。外部参考资料通过本机逻辑 ID 映射重新绑定，不随客户包泄露绝对路径；`.venv`和缓存默认重建，不视为可分发状态。

启动器必须检查：

- 产品根可写且路径安全；
- 空间足够；
- 必要依赖和字体状态；
- 数据库/schema 兼容；
- 路径链不存在越界链接；
- 本地端口可用且只绑定回环；
- 上次作业、检查点和恢复状态一致。

条件不满足时提供中文、可执行的错误说明，不部分启动后静默损坏数据。

## 5. 客户验收脚本

最终候选由不了解内部实现的用户视角完成：

1. 按文档验证发布包哈希；
2. 断开外网或启用仅回环环境；
3. 使用正式启动入口启动；
4. 查看一题的结构化题面、原图、来源页和 revision；
5. 执行条件、关键词和相似/语义搜索；
6. 审核一个解析依赖标签并查看证据；
7. 创建包含题型、分值、知识点、方法、难度、年份、预计用时的可行蓝图；
8. 锁题、换题并重新求解；
9. 创建不可行蓝图并查看具体缺口；
10. 一次生成五类文档；
11. 打开全部 PDF，检查题号、分值、图形、页码和答案映射；
12. 验证学生卷没有可见或隐藏答案信息；
13. 查看原图、已批准 SVG/TikZ并切回原图；
14. 从模板副本修改受控参数，执行字体校准和视觉回归；
15. 确认失败回归不能自动覆盖金标；
16. 创建完整备份；
17. 在 Test 安全实验室模拟活动副本损坏并恢复；
18. 重启并确认蓝图、审核、模板和导出快照；
19. 从恢复状态重新生成冻结试卷并比较内容和版式；
20. 检查网络、文件写入、隐私和审计报告。

全过程不得要求用户打开 SQLite、运行临时 Python 修复或调用隐藏测试接口。

## 6. 内容与版式标准

- 全部题目有稳定 ID、来源和审核 revision；
- 正式题目、答案、解析和标签均为批准版本；
- 五类文档来自同一冻结 PaperRevision；
- 题号、分值、顺序、答案和答题区完全一致；
- 学生卷无可见/隐藏答案泄漏；
- 解析缺失必须在正式构建前阻断或明确不进入正式包；
- PDF 尺寸、分页、字体、图形和页脚通过视觉门禁；
- NEW9 目标页具有完整回归结果；
- 图形原图始终保留，SVG/TikZ 可回退；
- 结构化输出具有可选择/检索文本，不以整页图片冒充；
- 原貌模式清晰标记，不和结构化模式混淆。

## 7. 数据、搜索和审核标准

- SQLite 为事实源，索引可重建；
- 蓝图只使用 approved/export-ready 题目；
- 正式知识点/方法标签有人审记录；
- 解析依赖标签绑定具体解析和证据；
- 内容变化使相关标签/embedding stale；
- 精确筛选结果正确；
- 语义检索达到冻结人工金标；
- 搜索结果显示来源、审核状态和匹配原因；
- 未审核候选不能静默进入正式试卷。

## 8. 备份恢复标准

一键备份至少覆盖：一致数据库快照、项目内原件、已发布派生资产、模板/字体配置/taxonomy、导出快照、审计和 manifest。

恢复必须：

- 先验证哈希、版本、路径和空间；
- 先恢复到 staging；
- 数据库/资产/引用和固定流程通过后再切换；
- 失败时保留当前活动状态；
- 有恢复前救援快照；
- 恢复后完成核心用户旅程。

当前只能写 Test，因此同盘备份不防整盘丢失。文档必须明确；异盘灾备需用户另行授权。

## 9. 离线与隐私

发布候选断网时必须完成全部核心流程，只允许回环通信。

必须证明：无 CDN、遥测、远程字体、远程 embedding/LLM、业务上传；本地 HTML 不执行外部脚本；PII 不进入测试报告、Git、索引和交付包。

## 10. 打印边界

在当前“只修改 Test”授权下，自动验收不操作真实打印机，因为打印池可能写系统目录。M5 必须完成 PDF 预检、标准阅读器/浏览器打印预览和本地渲染验证。

如要声称具体打印机完成实机验证，需另行获得用户授权并记录纸张、驱动、缩放和物理测量；此前只能声明“打印就绪 PDF”，不能声明“已实机打印验证”。

## 11. 发布质量门禁

发布仅在以下全部满足时允许：

- M0—M5 通过；
- 发布提交工作树干净，报告与产物来自同一 commit；
- 依赖锁定且 SBOM/许可完整；
- 正式数据、模板、字体和 taxonomy 版本冻结；
- release manifest 和文件哈希完整；
- 无 P0/P1；核心承诺范围内无 P2；
- 非核心 P2/P3 全部在已知问题中准确说明；
- 回滚和恢复路径实际验证；
- 客户验收脚本完整跑通；
- 产品/项目运行时 Test 外写入为 0；
- 非回环网络请求为 0；
- 用户确认最终交付。

## 12. 最终证据

交付报告列出：版本、提交、构建时间、支持/不支持范围、启动验证、用户旅程、五类输出、视觉/性能/安全/离线结果、恢复演练、字体与依赖许可、已知限制和回退步骤。

## 13. 最终判定

只有一个不了解内部实现的用户能依据文档完成：

```text
查题
→ 审核
→ 建蓝图
→ 组卷
→ 生成五类文档
→ 检查图形和排版
→ 备份
→ 恢复
→ 重启后继续使用
```

且全过程无开发者手工修库、无越界写入、无非预期联网、无答案泄漏、无数据丢失，才可把项目标记为“客户可交付”。
