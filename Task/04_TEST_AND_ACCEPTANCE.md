# 测试与真实用户验收规范

## 1. 核心原则

测试的目标是证明产品在真实资料、真实界面、真实失败和真实恢复条件下可用，而不是积累测试数量。

- 不以“至少 N 个测试”“代码覆盖率达到 X%”作为单独完成条件；
- 每条需求必须覆盖正常、边界、失败、恢复和安全路径中所有适用项；
- 单元测试、mock、API 直调和数据库查询不能替代用户界面流程；
- 自动测试通过但用户流程失败时，结论必须是失败；
- 视觉、打印、字体、来源追溯、答案泄漏、备份恢复必须使用真实产物检查；
- 跳过、xfail、未运行和环境缺失都视为未验证，必须在阶段报告披露；
- 不得删除失败测试、改变金标或降低阈值来获得绿色结果。

## 2. 需求—风险—证据追踪

每项需求建立唯一 ID，并维护：

```text
Requirement
→ Acceptance criteria
→ Risks
→ Test cases
→ Real user journeys
→ Evidence artifacts
→ Git commit / stage report
```

里程碑关闭前要求：

- 需求追踪覆盖 100%；
- 每个高风险需求至少有成功、失败、安全和恢复证据；
- 每个已知缺陷有严重级别、影响范围、复现步骤和处理决定；
- 不存在“已实现但没有验收入口”的功能。

测试数量由矩阵自然产生，不设上限，也不得为了减少工作量合并掉语义不同的场景。

## 3. 测试数据分层

| 层级 | 内容 | 用途 | 约束 |
|---|---|---|---|
| T0 合成夹具 | 小型、无版权/PII 的构造数据 | 单元、属性、攻击和故障测试 | 可进入 Git |
| T1 金标副本 | 从参考资料复制到 Test 后人工确认的代表页/题 | 集成、视觉和复核流程 | 原件不可提交 Git，证据用哈希/逻辑 ID |
| T2 目标全量 | 2020—2025 目标卷和合法本地资料 | M1/M5 全量与客户验收 | 只在本地，严格来源和许可记录 |
| T3 对抗数据 | 路径穿越、非法 SVG、损坏 PDF/备份、极端布局 | 安全、恢复和失败提示 | 不得包含真实 PII |
| T4 匿名测量数据 | 对成绩表脱敏后的副本 | 难度、区分度和统计校准 | 原始姓名、学号、IP、QQ 永不进入测试、索引或 Git |

测试不得直接修改 T1/T2 原件；每次运行使用版本化工作副本或可重建 staging。

## 4. 必需测试层

### 4.0 安全测试实验室

所有会写入、迁移、覆盖、隔离、恢复、制造损坏或验证删除的测试只能运行在：

```text
<PROJECT_ROOT>\tmp\test_lab\<run_id>\
```

路径越界测试不得把真实 Test 外目录作为攻击目标。应在 test_lab 中创建：

```text
<run_id>/project/    # 模拟允许写根
<run_id>/protected/  # 模拟根外受保护目录
```

即使被测 Guard 失效，实际写入仍留在 Test 内。实验室必须有匹配 run ID 的安全标记、无 Reparse Point，并在清理前生成逐文件 manifest。测试浏览器配置、TEMP、缓存和数据库也必须位于该 run 目录，禁止使用日常浏览器配置或活动业务库。

### 4.1 单元与属性测试

- 路径规范化、Guard、ID、哈希、状态机、约束和映射函数；
- 对中文路径、Unicode、空值、极值、顺序变化和重复输入做参数化/属性测试；
- 关键安全函数进行模糊输入、故障注入和边界分支检查；
- 覆盖率仅作为遗漏信号，不能替代行为证据。

### 4.2 契约与迁移测试

- portable root 必须覆盖中文/空格/不同父目录的合法模拟迁移，以及固定盘符残留、相对根、UNC、盘符根、缺失/篡改/硬链接 marker、Reparse 和非 NTFS 的失败关闭；迁移后旧物理路径证据不得冒充新基线；
- QuestionIR、FigureIR、PaperIR、manifest 和 API schema 往返；
- schema 升级、回滚、旧数据读取、重复迁移和中断恢复；
- 数据库`integrity_check`、`foreign_key_check`和业务不变量；
- 任何字段语义变化必须有迁移和兼容证据。

### 4.3 集成测试

- 文件系统、SQLite、渲染器、搜索索引、求解器、UI 和导出真实组合；
- 外部进程在受控 cwd/TEMP 下运行并检查额外输出；
- 不用 mock 掩盖 PDF、字体、TeX、Office 或数据库的真实兼容问题。

### 4.4 视觉与文档测试

- 固定引擎、字体、DPI、色彩和页面尺寸；
- 检查分页、纸张、边距、字体替代、基线、行距、题号、选项栏、图表、页脚和溢出；
- NEW9 和答题卡无文本层页面必须做整页栅格比较；
- 同时使用像素热图、关键锚点、文本/字体清单和人工叠图；
- 不用单一全页像素百分比掩盖局部严重错位；
- 所有 PDF 实际打开、逐页抽查并进入打印预览。

初始视觉门槛由 M0 金标测量冻结：页面尺寸和分页必须精确；主要锚点默认目标偏差不超过 0.5—1 mm；零裁切、零溢出、零静默字体替换。调整须有 ADR，不能为当前失败临时放宽。

### 4.5 安全测试

- WorkspaceGuard 攻击矩阵；
- 外部参考文件处理前后哈希；
- 外部进程旁路写入、缓存和链接逃逸；
- SVG/TeX/压缩包主动内容；
- 密钥、PII、大文件、原件和字体的 Git 暂存拦截；
- 本地服务仅回环、断网运行和 CSP；
- 禁止命令静态扫描和运行时文件审计；
- 产品和项目运行时的 Test 外写入数量必须为 0；依赖安装事务不在产品运行测试中执行，并按独立 manifest 审计。

### 4.6 约束与内容一致性测试

- 蓝图硬/软约束、不可行核心、确定性和相似冲突；
- 题目 revision、题号、分值、答案、解析、答题区和来源跨五类文档对应；
- 学生卷答案/解析泄漏扫描；
- 标签批准/拒绝/过期、解析证据和向量 stale；
- 图形 IR、SVG、TikZ 和原图切换的语义一致性。

### 4.7 备份与恢复测试

- 一致数据库快照、文件 manifest 和哈希；
- 完整、增量、重复备份和空间预检；
- 缺文件、篡改、损坏、旧 schema、路径穿越和恢复中断；
- staging 恢复、救援快照、活动状态切换和失败回退；
- 恢复后必须重跑固定真实用户旅程，不能只比较文件数量。

### 4.8 性能、稳定性与长时间测试

- 目标规模下搜索、预览、组卷、导出、索引、备份和恢复；
- 内存、句柄、临时文件、数据库连接和子进程无持续泄漏；
- 批量任务可显示进度、取消、重启和断点续作；
- 并发读/单写者约束有效；
- 小样测量后再全量，记录峰值磁盘、内存和时间。

客户体验默认目标：普通 UI 操作应立即反馈；超过 1 秒的任务显示状态；本地目标题库首屏搜索 P95 目标不高于 2 秒；长任务不能无进度假死。M0 可依据参考机器实测修订，但不得降低到明显不可用。

## 5. 真实用户旅程目录

下列旅程必须通过 UI 或正式公开入口执行，禁止直接改库或调用内部私有函数代替。

### 启动与状态

- UJ-001：fresh-user 断网首次启动，看到明确的初始化流程；
- UJ-002：关闭并重启，数据、模板、任务和错误状态保持；
- UJ-003：已有历史状态升级后正常启动，失败时回到旧状态；
- UJ-004：端口占用或子进程启动失败时给出可操作提示。

### 导入、来源和复核

- UJ-010：选择 Test 外 PDF，经 Copy 哈希登记后导入；
- UJ-011：真文本 PDF 正确提取并定位到源页；
- UJ-012：无文本轮廓/扫描资料进入人工复核而非伪造成功；
- UJ-013：跨页题、图文混排和多栏选项能正确查看与修正；
- UJ-014：用户在原貌/结构化对照中编辑题面、答案和解析并批准；
- UJ-015：重复导入不产生未解释重复，来源版本变化产生新 revision；
- UJ-016：损坏/超限输入安全失败且活动库不变。

### 标签与检索

- UJ-020：提交知识点/方法候选，绑定证据并人工批准；
- UJ-021：解析改变后相关标签和 embedding 标记过期；
- UJ-022：按年份、题型、分值、知识点和方法组合筛选；
- UJ-023：关键词全文检索并看到命中原因；
- UJ-024：自然语言/相似题检索并看到来源、分数和解释；
- UJ-025：未批准标签和 stale 索引不进入正式筛选。

### 蓝图与组卷

- UJ-030：创建包含全部七类约束的可行蓝图；
- UJ-031：不可行蓝图显示冲突和题库缺口，不生成伪成功卷；
- UJ-032：锁题、换题、排序、重算并保留历史；
- UJ-033：相同版本、候选池和种子重算结果一致；
- UJ-034：题库内容后续修订不改变已冻结 PaperRevision。

### 图形与模板

- UJ-040：几何题查看原图、SVG、TikZ、辅助线和建系版本；
- UJ-041：函数图和统计图的数据/刻度/标注正确；
- UJ-042：非法/主动 SVG 被拒绝并回退原图；
- UJ-043：编辑受控模板参数、预览、保存新版本；
- UJ-044：字体缺失被明确检测，不静默替代；
- UJ-045：视觉回归失败阻止模板激活，上一版本仍可用。

### 五类输出

- UJ-050：一次操作生成学生卷、教师卷、答案册、解析册和答题卡；
- UJ-051：五份题号、分值、答案、解析和答题区一致；
- UJ-052：学生卷没有答案、解析、教师提示或隐藏泄漏；
- UJ-053：A3/A4 答题卡布局与题型空间映射正确；
- UJ-054：打开、缩放和打印预览全部 PDF，无裁切和乱码；
- UJ-055：其中一份构建失败时整套不发布，旧套件仍可用。

### 备份、恢复和韧性

- UJ-060：用户一键备份并查看范围、进度、大小和验证结果；
- UJ-061：在 staging 恢复后启动应用并执行搜索/组卷/导出；
- UJ-062：损坏、缺文件、越界和旧版本备份被安全拒绝；
- UJ-063：恢复切换中断后回到旧活动状态；
- UJ-064：长任务取消、重启后从检查点继续，不重复覆盖；
- UJ-065：磁盘空间不足时停止写入，不自动删除内容；
- UJ-066：断网后全部核心功能继续运行；
- UJ-067：路径攻击和外部写入尝试有明确拒绝与审计。

M5 必须运行全部适用旅程；新增需求必须新增旅程和追踪，不能仅塞入已有编号而不验证其独特风险。

## 6. 端到端验收方法

1. 在`Test/tmp/acceptance/fresh-user/<run_id>`创建隔离状态；
2. 禁网或阻断所有非回环访问；
3. 按客户文档启动，而不是开发模式快捷命令；
4. 使用浏览器/正式 UI 完成旅程；
5. 记录操作步骤、截图、产物哈希、日志和结果；
6. 实际打开最终 PDF，逐页检查代表页和打印预览；
7. 备份、恢复、重启并重放固定旅程；
8. 检查外部源未变、项目/运行时 Test 外写入为 0；
9. 由独立审计角色复核证据与报告结论。

大体积截图、PDF 和备份证据保存在 Git 忽略的 Test 内证据目录；Git 只提交脱敏摘要、相对逻辑 ID 和哈希。

## 7. 缺陷严重级别

- P0：越界写删、数据不可恢复、凭据/PII 泄漏、错误正式答案、备份破坏活动状态；立即停止发布。
- P1：核心用户流程走不通、学生卷泄漏、五件套不一致、硬约束被放宽、严重排版不可打印；阶段不得通过。
- P2：有安全替代路径的非核心缺陷、局部性能或可用性问题；必须披露和排期。
- P3：不影响任务完成的小型视觉/文案问题；可进入已知问题，但不能系统性累积。

P0/P1 不得条件验收。P2 只有不影响客户承诺且有明确修复计划时才可条件接受。

## 8. 测试结果报告

每个阶段报告必须列出：

- 实际运行命令和环境；
- 通过、失败、跳过、未运行数量及原因；
- 需求追踪矩阵；
- 真实用户旅程步骤和证据；
- 视觉差异和人工判断；
- 故障注入与恢复结果；
- 性能/资源峰值；
- Test 外写入证明；
- 未验证项和已知缺陷；
- 为什么阶段可以或不可以进入下一阶段。
