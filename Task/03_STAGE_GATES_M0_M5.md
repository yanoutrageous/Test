# M0—M5 阶段路线与门禁

## 1. 总则

每个里程碑都是可独立恢复、可审计、可推送的产品增量。阶段报告必须区分：已实现、已自动验证、已跑真实用户流程、已人工/视觉审查、尚未验证。不得用“代码已合并”代替阶段完成。

每个里程碑统一执行：

```text
入场审计
→ 冻结范围和验收矩阵
→ 检查点与分支
→ 小型金标切片
→ 实现和分层测试
→ 真实用户流程
→ 独立安全/质量审计
→ staging 恢复或回滚演练
→ 阶段报告
→ 显式提交、普通 push、草稿 PR
→ 门禁决定
```

## 2. M0：安全、金标和数据合同

### 目标

建立后续长期自动化不会越权、不会以历史报告冒充事实，并拥有稳定版本模型和可量化正确标准的地基。

### 入场条件

- Task 规范已读且`execution_contract.json`可解析；
- 当前分支、远端、未跟踪资产和用户修改已确认；
- GitHub CLI 已认证，或明确记录仅远端发布阻塞；
- 当前数据库、文件数量、磁盘空间和依赖状态已只读盘点；
- 没有未处置的安全事故。

### 工作流

1. 冻结代码提交、活动数据库、目标 PDF、参考资产和依赖 manifest；
2. 实现统一`WorkspaceGuard`、Copy 台账、原子写入、隔离删除、作业目录和审计事件；
3. 封闭任意外部`db_path/project_root/output_path`，把外部进程缓存重定向到 Test；
4. 完成路径攻击、Junction、ADS、Zip Slip、TOCTOU 和禁止命令测试；
5. 建立参考资产目录与视觉/内容/评分/图形/测量学金标集；
6. 确认模板族：182×257、184×260、176×250、A4、A3 答题卡和长篇解析册；
7. 测量纸张、边距、字号、行距、分页、页脚、锚点和字体替代；
8. 设计并版本化`QuestionRevision`、`SolutionRevision`、`TagAssertion`、`FigureRevision`、`TemplateRevision`、`BlueprintRevision`、`PaperRevision`、`ExportBundle`和`BackupSet`；
9. 定义 QuestionIR、FigureIR、PaperIR 及来源/坐标/变换合同；
10. 在数据库副本上完成正向迁移、完整性检查、回滚和旧版兼容试验。

### 必须交付

- WorkspaceGuard 与全部写入口接入清单；
- 文件操作和 Copy 审计格式；
- 禁止命令/路径攻击测试报告；
- 当前事实基线 manifest；
- 金标样本目录、来源哈希和许可状态；
- 模板族与初始视觉阈值；
- 版本化领域模型、IR schema 和迁移规范；
- 数据库迁移/回滚证据；
- M0 阶段报告和安全证明。

### 真实流程

- 在 Test 内 fresh-state 初始化数据库和目录；
- 从 Test 外只读资料复制一个安全样本到 Copy，核对哈希和台账；
- 运行一个合法项目内写入和多个越界写入，确认前者成功、后者无副作用失败；
- 从迁移前数据库副本迁移，再回滚并启动旧读取路径；
- 打开金标目录并能定位来源文件与代表页面。

### 退出门禁

- Test 外写入为 0；
- 所有恶意路径被拒绝，合法中文路径通过；
- 所有生产写入口均通过 Guard；
- 迁移往返无数据损失，`integrity_check`和`foreign_key_check`通过；
- 金标覆盖全部目标模板族和关键版式变体；
- NEW9 无文本层、字体许可、当前数据库为空等事实已进入风险和验收设计；
- M0 无未披露 P0/P1 风险。

### 回滚与 Git

M0 失败时不迁移活动库，只保留候选和报告。使用长期集成分支`agent/m0-m5-local-v1`；全部门禁通过后才能创建 M0 checkpoint tag，不得直接推 main 或自动合并。

## 3. M1：真实题库生产线与高保真排版

### 目标

让一份真实完整试卷从安全副本进入题库，经过人工复核后，以稳定正式版式重建；随后扩展至目标集的可控批次。

### 入场条件

- M0 `ACCEPTED`；
- 活动 schema 和 IR 已冻结兼容版本；
- 金标、Copy、审计和 Guard 可用；
- 正式排版后端选型试验有明确 ADR。

### 工作流

1. 建立输入分类：真文本 PDF、无文本轮廓 PDF、扫描 PDF、图片集合；
2. V1 实现目标 PDF 与代表性来源，照片全自动化仅验证 IR 可承载，不追求无人复核；
3. 记录源哈希、页码、bbox、多边形、旋转/透视变换、裁切和跨页关系；
4. 生成原貌页、题目裁切和结构化候选，全部进入复核状态；
5. 人工确认题面、选项、小问、答案、解析、分值、来源、预计难度和预计用时；
6. 分离`design_difficulty`（越高越难）与`observed_p`（越高越易），不得混用；
7. 建立正式 PDF 后端，HTML 仅作快速预览；PaperIR 驱动两者；
8. 建立原貌轨与结构化轨，模板和字体全部版本化；
9. 对金标页面做整页、锚点、分页、溢出和字体替换检测；
10. 小批闭环通过后，分批扩展到 2020—2025 目标卷。

### 必须交付

- 可重复的导入批次与失败/复核队列；
- 来源、页坐标、裁切和内容版本追溯；
- 可用的人工复核 UI；
- 第一批正式可导出题目；
- 正式 PDF 渲染器与快速预览；
- NEW9 及其他模板族的版本化模板；
- 字体 manifest、替代声明和编译 manifest；
- M1 用户流程和视觉报告。

### 真实流程

- 选择 Test 外参考文件，经 Copy 后导入；
- 在 UI 中对照原貌修改一题并批准；
- 重启应用后仍可定位原文件、页面和裁切；
- 生成一份完整试卷，检查封面、题型、图表、跨页和页脚；
- 切换原貌/结构化显示；
- 重新运行同一批次不产生重复或漂移；
- 故意导入低质量或无文本样本，系统进入复核而非伪造成功。

### 退出门禁

- 一份完整真实试卷从导入到正式 PDF 全链路跑通；
- 正式池题目均有来源、分值、答案和审核状态；
- 缺解析题不能进入正式解析依赖流程；
- 同来源、同版本、同参数结果可重复；
- 代表金标页面尺寸/分页正确，零裁切、零溢出、零静默字体替换；
- 视觉偏差在 M0 定义阈值内并经人工叠图确认；
- 输入失败不污染活动库或正式资产。

### 回滚与 Git

导入和模板候选失败时活动版本保持不变；在长期集成分支上形成 M1 检查点。不得把原卷、Copy、活动数据库、字体或生成大文件提交 Git，只提交代码、schema、测试和小型许可明确的测试夹具。

## 4. M2：组卷蓝图与五类文档包

### 目标

从人工审核题库中按约束组卷，并从同一冻结试卷版本一次生成五类相互一致的正式文档。

### 入场条件

- M1 `ACCEPTED`；
- 正式候选池具有题型、分值、来源、答案、解析准备度等字段；
- 正式渲染器和至少一个模板族稳定。

### 工作流

1. 版本化蓝图：题型、分值、知识点、方法、难度、年份、预计用时和相似度约束；
2. 区分硬约束与软目标，正式标签仅使用 approved 断言；
3. 固定候选池哈希、求解器版本和随机种子；
4. 求解并输出入选理由、约束覆盖、相似/重复冲突和不可行核心；
5. 支持用户锁题、换题、排序和重新求解；
6. 冻结`PaperRevision`，题目后续变化不静默影响已冻结试卷；
7. 从同一 revision 生成学生卷、教师卷、答案册、解析册和答题卡；
8. 在 staging 中交叉核对题号、分值、答案、解析、作答区、图形和来源；
9. 五份全部成功后原子发布 bundle 和 manifest。

### 必须交付

- 蓝图编辑、版本和可行性诊断；
- 确定性约束求解与人工锁题/换题；
- 五类文档模板和生成器；
- A3 双页、A4 多页答题卡代表模板；
- bundle manifest、来源清单和构建日志；
- 答案泄漏、跨文档一致性和不可行诊断报告。

### 真实流程

- 创建可行蓝图并获得候选卷；
- 创建不可行蓝图并看到具体冲突，不产生伪成功卷；
- 锁定一题、替换一题、重算并保留操作历史；
- 修改题库后打开已冻结试卷，内容不漂移；
- 一次生成五份文件并通过 UI 访问；
- 检查学生卷无答案、教师卷有评分信息、答案册简洁、解析册完整、答题卡区域对应；
- 任一输出故意失败时，整套 bundle 不发布。

### 退出门禁

- 所有硬约束满足率 100%，不可行时不静默放宽；
- 同输入/版本/种子得到相同试卷；
- 五份文件题目 revision、题号、分值和答案映射 100% 一致；
- 学生卷零答案/解析泄漏；
- 正式 bundle 不含缺答案、缺解析或未审核题；
- 答题卡题号和空间映射与试卷一致；
- 全部输出通过视觉和真实打印预览检查。

### 回滚与 Git

五件套按单一 export ID 原子发布；在长期集成分支上形成 M2 检查点。任何构建分支失败不改变上一正式 bundle。

## 5. M3：图形、检索和模板维护闭环

### 目标

完成 SVG/TikZ 双轨、本地混合检索、解析证据标签、模板编辑和视觉回归，使系统具备长期维护能力。

### 入场条件

- M2 `ACCEPTED`；
- FigureIR、标签断言、模板版本和 PaperIR 合同稳定；
- 图形、搜索和视觉金标准备完毕。

### 工作流

1. 几何、函数、统计图建立 FigureIR；保留原裁切图和来源；
2. 从同一 IR 生成 SVG/TikZ，清洗 SVG，并做语义、数据、标注和黑白打印检查；
3. 人工批准后才改变首选图，失败时回退原图或上一版本；
4. 建立 taxonomy release、别名、废弃和迁移机制；
5. “极值点偏移”“端点效应”等标签绑定解析版本和证据步骤；
6. 机器建议进入候选/拒绝/批准队列；解析变化使相关标签和向量 stale；
7. 构建结构化过滤+FTS5+本地语义召回并解释匹配原因；
8. 模板编辑器只开放受控 token，不执行任意 TeX/命令；
9. 建立字体校准、叠图、热图、锚点和分页回归仪表盘；
10. 视觉基线更新作为独立受审计操作。

### 必须交付

- 三类 FigureIR、SVG/TikZ 生成与原图回退；
- SVG 安全验证器和非法样本；
- 标签版本、证据审核和失效队列；
- 本地 embedding/index manifest 和可重建命令；
- 混合搜索 UI、结果解释和相似题金标；
- 受控模板编辑器、字体校准和视觉仪表盘；
- M3 图形、检索、模板真实用户流程报告。

### 真实流程

- 对题干原图建立辅助线图和建系图，分别查看原图/SVG/TikZ；
- 非法 SVG 被拒绝且不影响原图；
- 提交解析依赖标签候选、审核批准、修改解析后看到 stale；
- 使用关键词、结构化条件、自然语言和“找相似题”检索，查看匹配理由；
- 从结果加入组卷，正式筛选不消费未批准标签；
- 编辑模板参数、预览、触发回归失败、回退上一模板；
- 模拟字体缺失，系统明确报错或声明替代，不静默切换。

### 退出门禁

- 未批准图形和标签不能进入正式输出/正式筛选；
- SVG/TikZ 与 FigureIR 语义一致且原图可回退；
- 索引可由主库完全重建，不是事实唯一来源；
- stale 向量/标签不冒充最新结果；
- 相似题/语义查询达到金标目标并无 PII 语料；
- 模板回归零新增溢出、零静默字体替换；
- 更新基线需有独立审批和差异理由。

### 回滚与 Git

在长期集成分支上形成 M3 检查点。图形、taxonomy、索引和模板分别拥有活动版本指针，可独立回退；不提交模型权重、缓存、未授权字体或真实成绩数据。

## 6. M4：完整备份、恢复和故障演练

### 目标

实现数据库、项目内原件、派生资产、模板、审计和导出快照的可信备份，并证明可以恢复，不只证明可以压缩或复制。

### 入场条件

- M3 `ACCEPTED`；
- 资产角色、活动版本、引用关系和 manifest 稳定；
- 磁盘可同时容纳活动状态、备份、恢复 staging 和救援快照。

### 工作流

1. 进入维护/只读状态并冻结写入；
2. 使用 SQLite 一致快照机制，不直接复制活跃 WAL 文件；
3. 汇集项目内原件、派生资产、模板、taxonomy、索引说明、导出快照和审计头；
4. 按哈希去重，生成相对路径、角色、大小、SHA-256和版本 manifest；
5. staging 构建备份，逐项复算哈希后原子发布；
6. 恢复包逐项拒绝绝对路径、`..`、链接、ADS、设备路径和资源炸弹；
7. 先恢复到 Test 内 staging，执行数据库、文件、引用和固定用户流程验证；
8. 创建恢复前救援快照，成功后原子切换活动 state；失败则保留旧 state；
9. 注入损坏、缺文件、旧 schema、低空间和中断等故障。

### 必须交付

- 完整/增量备份 UI 和 CLI；
- 不可变 backup manifest、浏览和验证；
- staging 恢复、救援快照、活动状态切换和自动回滚；
- 损坏包/路径穿越/中断恢复测试；
- 备份容量、时间和可重建资产策略；
- 明确“同盘备份不防整盘故障”的限制说明。

### 真实流程

- 用户点击备份并查看进度、内容、大小和验证状态；
- 在测试副本中修改/缺失数据后选择备份恢复；
- 恢复后重启应用，执行搜索、打开题目、组卷和固定导出；
- 损坏 manifest、删除资产、篡改数据库和构造路径穿越，恢复均安全拒绝；
- 恢复切换中断后仍能启动旧状态；
- 用户能查看和选择合法备份，不会误恢复候选/损坏包。

### 退出门禁

- 数据库行、关系、资产哈希、模板、taxonomy 和指定导出一致；
- 恢复后的固定用户流程全部通过；
- 损坏/不完整/越界包不得进入可恢复列表；
- 恢复失败不覆盖活动数据；
- 备份/恢复均无 Test 外写入；
- 真实恢复时间、空间要求和同盘限制已披露。

### 回滚与 Git

在长期集成分支上形成 M4 检查点。Git 只提交代码、测试、格式规范和小型合成夹具，不提交真实备份。阶段通过前不得在 UI 中宣称“一键恢复可用”。

## 7. M5：全量、离线和客户交付

### 目标

在目标资料和 fresh-user 环境中跑通所有能力，形成客户可直接使用的本地产品、示例成品、说明和恢复能力。

### 入场条件

- M0—M4 全部`ACCEPTED`；
- 无未关闭 P0/P1 缺陷；
- 许可、字体、隐私和交付范围已审计；
- 目标数据和视觉金标版本冻结。

### 工作流

1. 从单题、单页、单卷扩展到 2020—2025 新课标 I/II 和适应性测试目标集；
2. 分批生成并人工复核目标汇编和五类输出；
3. 执行全部需求—测试追踪、路径攻击、搜索金标、图形回退、字体和视觉回归；
4. 在`Test/tmp/acceptance/fresh-user/<run_id>`建立无历史状态环境；
5. 禁网运行安装/启动、导入、复核、搜索、蓝图、五类生成、备份和恢复；
6. 使用 UI 而非直接数据库或内部函数完成客户旅程；
7. 执行一次完整备份→恢复→重启→固定重渲染；
8. 生成产品包、用户手册、管理员/恢复手册、许可清单、限制说明和证据 manifest；
9. 独立做交付审计和客户视角验收；
10. 发布 release candidate；只在用户明确接受后进入正式发布流程。

### 必须交付

- 可启动的完全本地应用和离线依赖；
- 经过审核的题库状态、模板、taxonomy 和图形资产；
- 目标汇编及五类代表成品；
- 用户手册、故障排查、备份恢复和数据目录说明；
- 许可/字体/第三方依赖清单和可分发范围；
- 全量测试、真实流程、视觉、安全、性能和恢复证据；
- 已知限制、未纳入 V1 的内容和后续升级路径；
- 可验证 release manifest 和发布快照。

### 必跑客户流程

- 首次启动和现有数据启动；
- 导入并复核真实题目；
- 正式标签与本地混合检索；
- 可行/不可行蓝图、锁题和换题；
- 图形双轨和模板校准；
- 五类文档一次生成、查看和打印预览；
- 备份、故障恢复和重启继续使用；
- 断网、低质量输入、磁盘预警、失败重试和安全拒绝。

### 最终门禁

- 六项 V1 能力全部通过功能、失败和恢复路径；
- 需求到证据追踪覆盖 100%；
- fresh-user 断网全流程通过，无开发者后门步骤；
- 目标版式达到金标阈值并完成人工视觉验收；
- 五类输出一致且学生卷无泄漏；
- 完整恢复后全流程仍通过；
- Test 外写入为 0；
- 无未披露 P0/P1，P2 限制已在客户文档中准确说明；
- 交付物可由 release manifest 校验；
- 用户真实体验验收通过。

### 发布与目标完成

在长期集成分支上形成 M5 检查点并把草稿 PR 标记为可审查候选。禁止自动合并或直接推 main。只有以上全部事实成立且用户确认最终交付，长期目标才能标记完成。

## 8. 跨阶段一票否决项

以下任一项发生时，该里程碑不得通过：

- Test 外写入或无法证明写入边界；
- 原件/正式版本被候选覆盖；
- 数据库或备份完整性失败；
- 用户流程失败但自动测试通过；
- 学生卷答案泄漏或五类文档映射不一致；
- 蓝图硬约束被静默放宽；
- 未批准标签/图形进入正式结果；
- 静默字体替换、未审计基线更新；
- PII、密钥、原卷、字体或备份误入 Git；
- 无恢复点的高风险变更；
- 伪造、缺失或无法复现的验收证据。
