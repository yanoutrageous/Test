# 架构与实现规范

## 1. 总体架构

采用本地单机、分层单体优先的架构，避免在 V1 引入不必要的分布式服务：

```text
Local UI
→ Application Services
→ Domain / Versioned IR
→ SQLite Facts + File Asset Store
→ Controlled Local Tools
```

SQLite 是业务事实主库；文件系统保存原件、图形和导出。FTS、embedding、缩略图和视觉差异均为可重建派生物。

## 2. 安全执行层优先

任何业务开发前先具备：

- WorkspaceGuard；
- 原子写入；
- Copy/来源台账；
- job staging 和资源限额；
- 隔离删除；
- 审计事件；
- 安全外部进程包装器；
- SQLite 一致快照。

所有模块只能通过这些公共能力写盘或启动工具。禁止业务模块直接接受任意绝对输出路径。

生产根采用`PORTABLE_LOCAL_NTFS_V1`：从受信任根权限模块的位置发现仓库，以精确根标记验证项目身份，不接受 cwd、环境变量、配置或调用者注入。物理盘符和父目录属于每次启动的运行观察，不进入业务合同。持久数据、备份、manifest、URL 和客户包只保存项目相对路径或对象 ID；外部参考资料以逻辑 ID 关联 Git 忽略的本机只读映射。

## 3. 领域对象

核心版本化对象：

- `SourceFileRevision`、`SourcePage`、`SourceRegion`；
- `QuestionRevision`、`SolutionRevision`、`ScoringPointRevision`；
- `TaxonomyRelease`、`TagAssertion`；
- `FigureRevision`；
- `TemplateRevision`、`FontManifest`；
- `BlueprintRevision`、`CandidatePoolSnapshot`；
- `PaperRevision`、`ExportBundle`；
- `BackupSet`、`ActiveState`；
- `ReviewEvent`、`AuditEvent`。

活动状态通过显式 version pointer 管理，不把“最新修改时间”当成正式版本。

## 4. IR 合同

### QuestionIR

至少表达：题型、题面块、数学公式、选项、小问、图形引用、答案、解析、评分点、来源、分值、难度和时间元数据。

### FigureIR

- 几何：点、线、圆、角、平行/垂直/相切约束、辅助线和标注；
- 函数：表达式、定义域、采样区间、坐标轴、特殊点和渐近线；
- 统计：数据序列、组距、刻度、轴、图例和样式。

同一 FigureIR 生成 SVG/TikZ；两份独立手写源码不得冒充同源双轨。

### PaperIR

表达：卷头、说明、题型分区、题目 revision、编号、分值、选项布局、作答空间、分页提示、页眉页脚、文档角色和模板 token。

五类文档使用同一 PaperRevision/PaperIR，再按角色投影，禁止各自重新查询“最新题目”。

### 合同要求

- schema 有版本；
- 输入输出可验证；
- 序列化往返不丢语义；
- 未知字段兼容策略明确；
- 迁移、失效和回滚测试齐全；
- 路径使用项目相对路径或对象 ID。

## 5. 导入与内容生产

输入适配器至少区分：

- born-digital PDF；
- outline/vector PDF；
- scanned PDF；
- photo/image set。

统一输出来源页面、区域和候选 QuestionIR。自动识别不得直接进入 approved：

```text
imported
→ candidate
→ needs_review
→ approved / rejected / needs_recut
```

跨页、图文关联、公式识别和题号锚点都保留置信和证据。照片全自动化不作为 V1 门禁，但 schema 和接口不得写死为 PDF 矩形裁切。

## 6. 正式排版

- HTML 作为交互预览，不是唯一正式输出后端；
- 正式 PDF 后端通过 M0/M1 ADR 和金标试验确定，优先评估能够稳定控制中文字体、数学公式、分页和 TikZ 的方案；
- PaperIR 是预览和正式输出的共同内容源；
- 模板使用声明式 token，不在题目数据中散落版式代码；
- 固定依赖、字体和编译环境，输出 manifest 记录版本；
- 原貌轨和结构化轨并存并清晰标识；
- 编译禁用 shell escape，输入输出根受限；
- 正式输出必须可重复、可追溯、可视觉回归。

## 7. 蓝图与求解

蓝图支持硬约束、软目标、权重、范围、分布和冲突：

- 题型、总分和各题分值；
- 知识点、方法及覆盖/配额；
- 预计/实测难度分布；
- 年份和来源多样性；
- 总预计用时；
- 相似度和重复题冲突；
- 人工锁题、排除和顺序。

求解必须：

- 固定候选池、版本、种子和算法版本；
- 硬约束 100% 满足；
- 解释每题入选和未满足软目标；
- 不可行时输出冲突/缺口，不自动放松；
- 保留用户锁题/换题历史；
- 冻结 PaperRevision，隔离后续题库变化。

## 8. 五类文档

一次构建任务生成：

- 学生卷；
- 教师卷；
- 答案册；
- 解析册；
- 答题卡。

所有文件先进入同一 staging，统一核对题号、分值、答案、解析、评分点、图形和作答区。全部成功后以单一 export ID 原子发布。

学生卷泄漏检查包括可见内容、文本层、隐藏对象、附件、书签、元数据、替代文本和打包文件名。

## 9. 图形双轨

图形状态：

```text
original
→ figure_ir_candidate
→ svg/tikz_candidate
→ reviewed
→ approved_preferred
```

任何候选失败时正式输出继续使用原图或上一批准 revision。SVG 解析采用安全模式；TikZ 不允许读写任意文件或执行命令。

## 10. 标签和检索

检索分层：

1. 普通列结构化过滤；
2. SQLite FTS 全文召回；
3. 本地 embedding 相似/语义召回；
4. 排序、去重和结果解释。

规则：

- 正式筛选只使用 approved 且非 stale 标签；
- embedding 只处理已审核、非 PII 内容；
- 索引保存模型、内容和 taxonomy 哈希；
- 索引可全量重建；
- 结果显示来源、审核状态、匹配字段和语义理由；
- 语义质量使用冻结人工金标，不凭单个余弦阈值判断。

## 11. 模板编辑和视觉仪表盘

- 只开放纸张、边距、字体、字号、行距、标题、选项列、页脚、留白等受控参数；
- 每次编辑创建新 TemplateRevision；
- 实时预览与正式 PDF 使用同一 token 语义；
- 字体校准检测字形覆盖、基线、宽度、数学字体配对和替换；
- 仪表盘展示页数变化、锚点差、热图、裁切、溢出和字体变化；
- 更新基线是独立高风险操作，不能由实现自动触发。

## 12. 备份恢复

- 使用 SQLite Backup API 或等价一致快照；
- backup manifest 使用相对路径、哈希、角色和版本；
- 构建 staging 后验证再发布备份；
- 恢复逐项防路径穿越和资源炸弹；
- 先恢复到新 state，检查数据库、文件、引用和固定用户流程；
- 创建恢复前救援快照后再切换`active-state.json`；
- 切换失败指回旧 state，不原地覆盖；
- 备份存在不等于可用，必须真实恢复。

## 13. UI 与本地服务

- UI 是核心业务入口，不把关键流程藏在 CLI；
- CLI 可用于自动化和诊断，但与 UI 调用同一 application service；
- 服务只绑定回环；
- 静态依赖全部本地化，无 CDN、遥测和远程字体；
- 长任务有进度、取消、失败说明和恢复入口；
- 错误信息使用中文并提供用户可执行下一步；
- 不在错误消息、页面、URL 或日志泄露外部绝对路径和 PII；
- 核心流程支持键盘操作、清晰焦点和可读缩放。

## 14. 数据库与迁移

- migration 仅向前追加，禁止编辑已发布迁移；
- 每次迁移有 schema version、事务边界、前置条件和兼容策略；
- 首次迁移只在副本运行；
- 大迁移分批、可恢复并记录游标；
- 迁移前一致快照，迁移后完整性和业务不变量；
- 不使用直接文件复制备份活动 WAL 数据库；
- 绝对路径不进入业务表。

## 15. 工程质量

- Python 使用类型注解、明确异常和小型可测试模块；
- 配置有 schema、默认值和版本，不能散落魔法常量；
- 时间使用带时区格式，ID/哈希生成确定；
- 日志结构化、脱敏并带 run/job/operation ID；
- 错误区分用户输入、资源、外部工具、数据完整性和安全拒绝；
- 重试只用于幂等且明确可重试错误；
- 测试不能依赖执行顺序或真实用户全局目录；
- 关键算法和安全边界有属性/故障注入测试；
- 新依赖先审计必要性、许可、来源、更新和离线分发。

## 16. 可观测与证据

每个 job 记录：输入/配置/工具链哈希、声明写范围、开始结束、资源、产物、验证、失败和恢复点。业务审计与文件审计使用 operation ID 关联。

不得记录题目正文、完整解析、个人信息、密钥和业务原件内容到一般日志。阶段报告使用脱敏摘要和证据哈希。

## 17. 禁止黑盒成功

以下实现不得进入正式发布：

- 无法解释来源或版本的题目；
- 无法说明约束为何满足的组卷结果；
- 五类文档分别查询最新数据；
- embedding 或模型输出直接成为正式标签；
- 视觉金标由被测代码自动覆盖；
- 备份未恢复过；
- 只有 API/脚本能操作而 UI 不可用；
- 需要开发者手动改数据库才能完成客户流程。
