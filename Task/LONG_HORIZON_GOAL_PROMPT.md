# 长时间目标执行提示词

## 使用方法

下一次对话开始长期工作时，将下面“目标提示词”完整发送。执行者必须把`Task`目录视为规范来源，并从`RUN_STATE.json`恢复，不得从头凭记忆重做，也不得提前宣称完成。

## 目标提示词

```text
请在当前包含`.exam-bank-root.json`且通过`app/project_root.py`验证的本机 NTFS 项目根中
创建并持续执行一个长期目标：严格依照该根`Task`下的全部规范，从当前 RUN_STATE 开始，连续完成
M0、M1、M2、M3、M4、M5，直到形成真实可用、可恢复、可追溯、可直接交付客户的
本地高中数学题库与组卷系统。

终局不是“代码写完”或“测试通过”，而是客户无需接触源码即可在断网环境中通过正常界面完成：
导入/查看来源 → 复核题目 → 标签审核与检索 → 创建并求解组卷蓝图 → 锁题/换题
→ 查看原图和 SVG/TikZ → 编辑模板并校准字体 → 一次生成学生卷、教师卷、答案册、
解析册和答题卡 → 检查视觉回归 → 一键备份 → 在 staging 恢复 → 重启后继续使用。

开始前必须依次阅读：
1. Task/execution_contract.json
2. Task/README.md
3. Task/00_CORE_EXECUTION_PLAN.md 至 Task/11_REFERENCE_BASELINE.md
4. Task/CURRENT_STATUS.md 与 Task/RUN_STATE.json
5. AGENTS.md、Base/Base.md 和当前相关代码

不可变安全底线：
- 盘符和父目录可随整根迁移改变，但 cwd、环境变量、配置或调用者参数不能授予根；项目数据、日志、缓存、模型和运行时唯一允许写、改、移动、删除的位置是经 marker 验证的 PROJECT_ROOT。只有依赖审计批准的包管理器事务可写其已登记的程序/卸载位置，且不得承载任何项目数据。
- PROJECT_ROOT 外资料如需转换、OCR、裁切、排版、字体分析或任何可能产生副作用的处理，
  必须先复制到 PROJECT_ROOT\Copy，核对 SHA-256 并登记；之后只处理副本。
- 禁止无界递归删除、通配符删除、目录镜像清理、磁盘/分区操作、git reset --hard、
  git clean、force push、直接覆盖原件或已发布版本。
- 删除业务内容只能先移入 Test 内 quarantine；自动任务不得永久清空隔离区。
- 所有临时目录、缓存、Office/TeX/OCR/模型配置和输出都必须重定向到 Test 内作业目录。
- 不上传原卷、题库、成绩、备份、字体或其他业务资料；断网必须可运行。
- 正式标签必须绑定解析版本和证据并经过人工审核；机器结果只能是候选。
- 任何路径边界、备份、数据库完整性、磁盘空间、项目/运行时 Test 外写入，或安装器超出审计 manifest 的异常，都要立即停止相关写入，
  保留现场并按安全事故流程处理。

长期执行方式：
- 先做 M0 入场审计，不跳阶段；每个切片都执行“检查点→候选→自动测试→真实用户流程
  →安全审计→阶段证据→Git 提交/push”。
- 使用 Task/RUN_STATE.json 记录状态和可恢复点；任务中断后从该状态继续，不重复已验证工作。
- 活跃工作期间持续给出简洁进度；长命令使用可等待/可恢复机制，不无休止阻塞。
- 同类失败最多进行两次有依据的修正尝试；第三次仍失败时记录 BLOCKED，继续不依赖它的工作，
  不循环碰撞。
- 非底线且可逆的技术决策可选择更简单、本地、可测试的方案并写 ADR 后继续。
- 会改变需求、验收口径、字体/许可声明、安全边界、远端历史或产生不可逆影响的决策必须暂停，
  给出事实、选项、影响和推荐，请求用户决定。
- 用户允许在审计证明“不安装将阻断已批准目标”时安装必要依赖；默认优先项目内便携安装。
  系统级安装、驱动、服务、管理员权限、许可不清或未知来源仍必须暂停。每次依赖变更都要记录
  来源、版本、许可、哈希、写入位置、必要性和回滚方法。

测试与验收：
- 不设置“写够 N 个测试即完成”的指标。每条需求必须映射正常、边界、失败、恢复和安全路径。
- 必须包含单元、属性/模糊、迁移、契约、集成、视觉、性能、安全、备份恢复和端到端测试。
- 每个阶段必须通过 Task/04_TEST_AND_ACCEPTANCE.md 定义的真实用户旅程；不能用直接改数据库、
  调内部函数或黑盒脚本代替用户界面流程。
- 自动测试与真实用户体验冲突时，以失败处理，查明根因；不得更新金标掩盖退化。
- M5 必须在 Test 内 fresh-user 隔离环境、断网条件、真实目标资料上完整跑通，并输出可审阅证据。

Git 与发布：
- 远端固定为 https://github.com/yanoutrageous/Test.git；M0—M5 使用长期集成分支
  agent/m0-m5-local-v1、一个持续更新的草稿 PR，以及每个里程碑的不可移动 checkpoint tag。
- 只显式暂存本切片文件；不得把 Base、Copy、数据库、备份、原卷、模型、字体、导出大文件、
  PII、密钥或无关用户修改加入 Git。
- 每个已验证切片可普通 push 作为检查点；阶段只有通过全部门禁后才能标记 accepted。
- 禁止直接推 main、自动合并、强推、删除远端引用或重写历史；回滚使用新提交/revert。

最终交付必须符合 Task/10_DELIVERY_DEFINITION.md，包含可启动应用、离线依赖、经过审核的数据与模板、
五类示例成品、完整备份恢复、用户手册、管理员/恢复手册、许可和限制说明、阶段证据及发布清单。

除非真正达到上述终局或触发无法在授权范围内解决的硬阻塞，否则不要把长期目标标记完成。
```
