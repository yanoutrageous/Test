# 数据与资产治理规范

## 1. 原则

- SQLite 保存业务事实、版本、状态和相对路径；大文件保存在文件系统；
- 原件、规范化内容、派生资产、索引、导出和备份严格分层；
- 原件只增不改，派生物可重建，正式发布不可覆盖；
- 所有对象有稳定 ID、内容哈希、来源和版本；
- 任何自动结果先候选后审核；
- PII、许可不清资产和业务事实不得混入日志、搜索索引、Git 或客户包。

## 2. 建议存储分区

```text
D:\AAA命题\Test\
├─ Base\                         # 已在项目内的参考原件，只读保护
├─ Copy\
│  ├─ source\<copy_id>\         # 外部资料不可变副本
│  ├─ restricted\<copy_id>\     # 含 PII/受限内容的临时受控副本
│  ├─ work\<classification>\<copy_id>\<job_id>\  # 分类隔离加工工作区
│  └─ ledger\                    # Copy 台账
├─ data\
│  ├─ db\versions\<state_id>\
│  ├─ originals\<object_id>\
│  ├─ derived\<kind>\<pipeline_version>\
│  ├─ indexes\<index_version>\
│  ├─ templates\<template_id>\<revision>\
│  ├─ exports\<export_id>\
│  ├─ snapshots\<snapshot_id>\
│  └─ quarantine\<classification>\<date>\<event_id>\
├─ backups\<backup_id>\
├─ logs\audit\
└─ tmp\jobs\<classification>\<job_id>\
```

现有目录不要求立即搬迁；M0 先登记角色和保护规则，后续增量纳入。任何迁移都必须有 manifest、staging 和回滚。

## 3. 资产角色

### 原件

包括原 PDF、DOCX、图片、原始裁切和经 Copy 验证的副本。

- 写入后不可修改或覆盖；
- 同内容按哈希去重，但来源记录可多条；
- 新版本作为新对象，不替换旧对象；
- 保留来源路径、文件哈希、大小、时间和许可状态；
- Test 外路径只进入本地受限台账，不进入 Git 或客户报告。

### 规范化内容

包括题面、选项、小问、答案、解析、评分点、来源和结构布局。

- 每次修改形成 revision；
- 已冻结 PaperRevision 始终引用精确 revision；
- 未审核 revision 不进入正式导出；
- 内容变化必须使相关索引、标签和视觉结果失效或重建。

### 派生资产

包括页图、裁切、缩略图、OCR、公式候选、SVG、TikZ、预览、差异图和 embedding。

- 记录源对象哈希、管线版本、参数、工具版本和生成时间；
- 可重建，不能成为唯一事实来源；
- 重跑产生新 revision，不覆盖已发布派生物；
- 未审核矢量图不改变正式首选资产。

### 导出快照

每次五类文档构建形成唯一`export_id`，包含：

- PaperRevision、BlueprintRevision；
- 题目/解析/图形 revision；
- 模板、字体、taxonomy 和求解器版本；
- 构建参数、随机种子、文件哈希和来源表；
- 五类文档及 bundle manifest；
- 验收和已知偏差。

已发布快照不可原地覆盖。

## 4. 路径与哈希

- 数据库业务路径只能保存项目内规范化相对路径；
- 禁止绝对路径、`..`、盘符和外部 URL；
- 本地受限 Copy 台账可记录外部绝对源路径，但不得提交 Git；
- 文件事实至少使用 SHA-256；
- 大文件可增加分块哈希，用于增量备份和损坏定位；
- 业务 ID 不依赖临时文件名或自增主键；
- 用户改名或移动受控资产时必须通过应用流程更新 manifest，不能直接文件系统拖动。

## 5. 来源追溯

题目至少能够追溯到：

```text
SourceFileRevision
→ SourcePage
→ Region/Polygon
→ TransformChain
→ QuestionRevision
→ SolutionRevision
→ FigureRevision
→ PaperRevision
→ ExportBundle
```

对图片输入预留：原始尺寸、EXIF 是否保留、旋转、裁边、透视、去阴影、去弯曲、OCR 区域、公式候选、置信度和人工修订。

来源无法确认时必须标记`unknown`或`inferred`，不得把推测写成事实。

## 6. 标签和解析证据

正式 taxonomy 版本化并支持父子关系、别名、废弃和迁移。

每个标签断言至少记录：

- question revision；
- taxonomy release 和 concept ID；
- 状态：candidate/approved/rejected/stale；
- 来源：人工、规则、模型；
- 绑定的 solution revision；
- 证据步骤或文本范围；
- 审核人、时间和理由。

“极值点偏移”“端点效应”等依赖解析的标签，没有具体解析证据不得批准。题面或解析变化时相关断言自动 stale。

## 7. 难度和用时

不得混用以下概念：

- `design_difficulty`：人工预计难度，推荐 1—5，值越大越难；
- `observed_p`：实测得分率，值越大越容易；
- `expected_time_seconds`：人工审核的预计作答时间；
- `observed_exam_time_seconds`：整卷完成用时；
- `observed_item_time_seconds`：只有数据源真实提供逐题停留时间时才填写。

模型可提供建议值和置信区间，但正式蓝图使用的字段必须标明来源和审核状态。学生群体变化会影响实测难度，统计值必须绑定考试、样本筛选规则和时间。

## 8. 个人信息

现有成绩表可能包含姓名、学号、身份证式标识、QQ、IP、进入/交卷时间和逐题得分。

规则：

- 原始表默认留在 Test 外只读位置，不进入题库、embedding、日志、Git 或客户包；
- 必须处理时复制到`Copy/restricted`，标记 restricted，工具缓存全部重定向；
- 在受控 job 内生成不可逆匿名 ID 和最小化字段的脱敏数据；
- 脱敏后进行重识别风险检查；
- 日志只记行数、字段类别和哈希，不记实际姓名、学号、IP、QQ；
- restricted 副本不进入常规备份；用途完成后移入隔离区，永久清理另行审批；
- 测量学结果与题库事实分表保存，不用成绩覆盖人工预计难度；
- 客户交付包不得含任何原始个人数据。

## 9. 图形治理

每幅图可包含：

- 原始裁切图；
- FigureIR；
- SVG revision；
- TikZ revision；
- 题干图、辅助线图、建系图等用途变体；
- 审核状态和回退目标。

审核同时检查：几何/函数/统计语义、数值、刻度、标注、线型、字体、黑白打印和安全性。视觉相似但数学关系错误必须拒绝。

## 10. 模板和字体

- 模板只能创建新 revision；已用于 export 的版本不可修改；
- 编辑器只开放受控 token，不直接保存任意可执行 TeX；
- 字体 manifest 记录文件/系统字体名称、版本、哈希、字形覆盖、宽度/基线、数学字体配对、许可和替代策略；
- 方正、汉仪等商业字体未经确认不得打入客户包；
- 系统字体可用于本机内部渲染不等于拥有再分发权；
- 字体缺失或替换必须显式报错/披露，不静默降级；
- 目标文件字体不可识别时只能建立视觉等效金标，不能虚假宣称精确字体复刻。

## 11. 版权与交付范围

外部真题、第三方模拟卷、解析、图形和字体可能受版权/许可限制。本地个人处理和客户分发是不同边界。

- 来源和许可状态必须登记；
- 未确认可分发的原件不进入 Git、安装包或客户示例；
- 客户包优先包含程序、元数据、用户自有资料导入能力和自制/许可明确样例；
- 无法确认许可时标记`local-use-only`并阻止对外发布；
- 交付说明准确列出客户需要自行提供的字体或资料。

## 12. 索引和模型

- FTS 和 embedding 是可重建派生层；
- 只对已审核、非 PII 的内容建正式索引；
- 保存模型、分词、维度、归一化、内容哈希和索引版本；
- 题面/解析变化后旧向量 stale；
- 模型权重不进入 Git，许可和来源纳入依赖清单；
- 本地模型服务只绑定回环，不遥测、不下载运行时更新。

## 13. 备份范围

标准完整备份包括：

- SQLite 一致快照；
- 项目内业务原件；
- 已发布派生资产；
- 模板、字体配置、taxonomy；
- 导出快照；
- 审计头、版本和 manifest。

可重建缓存和索引可选择不存二进制，但必须保存重建版本/参数并在恢复演练中重建。`Copy/restricted`、tmp、浏览器状态和未发布失败产物默认排除并明确记录。

## 14. 保留和隔离

- 原件、批准 revision、发布 bundle、里程碑备份和审计记录长期保留；
- 候选和失败产物按阶段策略保留至验收结束；
- 业务删除先进入隔离区；
- 自动运行期间不永久清空隔离区；
- 因空间需要清理时生成精确清单、引用检查和恢复方案，按 D3 请求用户。
