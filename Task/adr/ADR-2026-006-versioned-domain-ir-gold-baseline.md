# ADR-2026-006：版本化领域、IR 与金标基线

- 状态：Accepted（M0 合同基线；未激活生产写入或正式视觉产物）
- 日期：2026-07-25
- 决策级别：D2
- 影响里程碑：M0—M5
- Requirement IDs：`M0-DOMAIN-001`、`M0-GOLD-001`、`M0-GOLD-002`
- 补充：`ADR-2026-003`、`ADR-2026-004`、`ADR-2026-005`

## 背景与已确认事实

后续导入、复核、组卷、五类文档、图形、搜索、备份和恢复必须引用同一批不可变对象，
不能在每个阶段各自读取“当前最新”记录。参考资料同时包含内容、版式、评分、图形、失败样本、
标签和测量学真值；其中 NEW9 为 91 页无文本层视觉资料，多种纸张尺寸并存，字体和许可状态也
不能从外观推断。

活动数据库仍为 legacy `user_version=0`，生产 writer 仍断开。本决策只冻结可验证合同与
本地金标登记，不迁移活动库、不复制外部原件、不激活正式模板，也不把许可未知资料加入客户包。

## 约束与不可变底线

- 领域对象、IR、模板和金标均使用显式版本与内容哈希，不提供可漂移的`latest`别名。
- 未知顶层字段失败关闭；兼容扩展只能位于受控`extensions`对象。
- 所有持久路径使用项目相对路径或稳定对象 ID；本机绝对映射只在 Git 忽略的
  `Task/local/`中保存。
- 外部参考资料只读指纹化；使用前必须走 Copy 流程，原件不得被测试或工具改写。
- `design_difficulty`越高越难，`observed_p`越高越易；两者不得复用字段。
- 没有逐题真实用时时，`observed_item_time`必须为空，不得从整卷时长伪造。
- 视觉基线不能原地覆盖；更新必须形成新 revision、变更理由和 D2 审计。

## 候选方案

### 方案 A：可变业务行加“当前版本”查询

- 做法：在现有表上直接加字段，消费者运行时读取最新行。
- 优点：代码少。
- 风险/成本：五类文档可能在构建期间分别读到不同版本；迁移、回滚和审计无法绑定精确字节。
- 回滚：只能依赖数据库快照，不能对单个对象确定回滚。

### 方案 B：不可变 revision + 版本化 IR + 逻辑金标登记

- 做法：对象 revision、IR schema、模板族、视觉阈值和金标 registry 分别版本化并规范哈希。
- 优点：引用精确、可复现、可迁移、可回滚；本机路径和不可分发原件不进入 Git。
- 风险/成本：消费者必须显式携带 revision ID，旧版 schema 需要迁移器。
- 回滚：恢复前一 revision 或把 v1 IR 确定性回滚为受支持的 v0.9。

## 决定与理由

采用方案 B，并冻结以下合同：

1. `DomainRevision` v1 覆盖 19 类不可变对象：来源文件、页面、区域、题目、解析、评分点、
   taxonomy、标签断言、图形、模板、字体清单、蓝图、候选池快照、试卷、导出包、备份集、
   活动状态、复核事件和审计事件。字段集合精确，时间为带时区 UTC 语义，前驱与引用显式，
   canonical JSON 决定 revision hash。
2. `QuestionIR`、`FigureIR`、`PaperIR`冻结为 v1。schema 往返必须保持 canonical bytes；
   v0.9→v1 迁移和 v1→v0.9 回滚为确定性函数，不能静默丢弃非默认语义。
3. 来源区域固定坐标空间、单位、边界和有序 transform chain；每个变换的输入空间必须等于
   上一步输出空间。跨页、旋转和透视信息不能只留在渲染器临时状态。
4. `QuestionIR`分别记录设计难度、实测 P、预计用时、实测逐题用时、评分点和图形精确引用。
   合成测量夹具用 8 个匿名对象、4 个题目验证 P 值，明确只有整卷时长而无逐题实测时长。
5. `FigureIR`为几何、函数、统计三类提供语义数据与约束；正式图形仍须 M3 人工批准和原图回退。
6. 五类文档是同一`PaperIR`和同一`PaperRevision`的角色投影；题目、模板和字体引用均为精确
   revision，不允许各输出独立解析“最新”。
7. 金标 registry 使用逻辑 ID、成员 ID、SHA-256、字节数、结构状态、真值角色、许可和 PII
   分类。当前冻结 18 个逻辑条目、63 个成员、8 个真值角色和 12 个模板族；外部源保持
   copy-on-use。
8. 页面尺寸按 exact reference；表示误差上限 0.01 mm，主要锚点目标/硬上限为
   0.5/1.0 mm，裁切、溢出和静默字体替换均为 0。像素指标只作诊断，不能覆盖锚点、分页、
   字体清单和人工叠图失败。
9. 许可状态`unverified`或 PII 状态`unknown/internal`只允许留在本地受限流程，不能据此声称
   可客户分发。

## 安全、数据、许可和客户体验影响

- Git 中只保存合同、小型合成夹具、逻辑登记和哈希；不保存外部原件、真实姓名、绝对路径或
  未授权字体。
- 金标构建器固定项目 cwd 和项目内输出，只读验证本机映射，拒绝 hardlink、Reparse、
  重解析和源哈希变化；本轮外部复制数为 0。
- 当前 registry 有 4 个`local-use-only`、11 个`user-owned`、1 个`synthetic`和
  2 个`unverified`条目；PII 分类为 14 个`none`、3 个`internal`和 1 个`unknown`。
  这些状态是发布门，不是许可结论。
- 合同能防止版本漂移和语义混用，但不代表真实 PDF 已达到视觉阈值，也不代表图形或字体已获
  正式批准。

## 迁移、兼容与回滚

- v1 reader只接受精确 schema ID/version；未来扩展必须新增 schema 或使用受控
  `extensions`，不能修改既有字段语义。
- v0.9 迁移先验证旧结构，再生成 v1；回滚仅在 v1 数据可无损表达为 v0.9 时允许，否则
  明确拒绝。
- 领域 revision不可覆盖；活动指针变更属于后续独立事务。本 ADR 不创建或移动活动指针。
- 金标更新新增 revision和`previous_aggregate_sha256`，旧文件和旧 registry保留；失败时继续
  使用当前已验证版本。

## 验证和真实用户流程

- `tests/test_domain_models.py`验证 19 类对象、字段、哈希、时间、前驱和路径合同。
- `tests/test_ir_contracts.py`验证三类 IR、三类 FigureIR、坐标/变换、难度/时间语义、
  五类文档投影、迁移与回滚。
- `tests/test_gold_registry.py`验证 18/63 登记、8 个角色、12 个模板族、许可/PII、视觉阈值、
  NEW9 91 页、损坏 SVG 失败角色和合成测量事实。
- `RUN-20260725-M0-S5-122`通过 460 项 S5 门。
- `RUN-20260725-M0-S5-FULL-123`通过 1105 项全仓测试，另 1 个真实目录 symlink 能力用例按
  已记录的 WinError 1314 普通账户限制排除；全部安全证据通过。
