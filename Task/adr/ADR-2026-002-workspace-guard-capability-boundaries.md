# ADR-2026-002：WorkspaceGuard 只签发候选路径，生产写入必须使用受控能力

- 状态：Accepted
- 日期：2026-07-11
- 决策级别：D2
- 影响里程碑：M0—M5
- Requirement IDs：`M0-SAFE-001`、`M0-SAFE-002`、`M0-SAFE-005`、`M0-SAFE-006`
- 补充 ADR：`ADR-2026-001-central-workspace-guard.md`

## 背景

M0-S1 的独立安全审查确认：纯路径词法检查和逐层 `lstat` 可以拒绝稳定状态下的越界、ADS、Junction、Reparse Point 与硬链接写目标，但不能把“检查通过”和随后的 `open/replace/move`变成同一个原子动作。检查后仍可能发生父目录替换、硬链接插入或目标身份变化。

审查同时发现三个必须显式编码的能力边界：生产授权根不能由调用者扩大；永久保护目录和只增不改目录不能只依赖调用者自律；业务删除不能作为通用路径意图存在。

## 决定

1. M0-S1 的`WorkspaceGuard`定义为**无副作用候选路径校验核心**，不是安全 writer，也不直接授予文件系统修改能力。
2. Guard 每次授权都重新核对从卷根到`authorization_root`、`workspace_root`和目标最近现存父目录的身份；根链变化、Reparse、身份字段缺失或不稳定时失败关闭。
3. 显式空 workspace 必须拒绝，不能回退到更宽授权根；`CREATE_DIRECTORY`必须是缺失目录目标；枚举参数必须运行时严格校验。
4. 现存多硬链接普通文件的变更意图保守拒绝，直到句柄级 writer 能证明具体操作不会写穿到其他目录项。
5. 通用`DELETE_TARGET`能力不存在。业务对象只能由后续成对授权的 quarantine source/target 能力移动到固定隔离根；临时实验室清理需要独立 job manifest 能力。
6. M0-S2 必须增加固定`PROJECT_ROOT`和原生探针的生产工厂、保护目录/只增不改/追加策略、job/调用者/用途上下文和入口静态扫描。
7. M0-S3 必须实现句柄级不跟随 Reparse 的 writer、独占新建、截断前身份检查、原子发布以及与原票据绑定的写后核验。

## 当前允许的声明

允许声明：当前核心能在无写副作用的候选判断阶段拒绝已覆盖的稳定路径攻击，并能检测跨调用的根链和目标身份变化。

禁止声明：生产写入已原子安全、TOCTOU 已关闭、所有永久保护策略已接入、`M0-SAFE-001/002`已通过或可以开始处理真实资料。

## 实际 symlink 环境门禁

本机普通用户创建目录 symlink 两次均返回 WinError 1314。按安全边界不启用开发者模式、不提升权限、不修改安全策略。真实 Junction、未知 Reparse tag 和合成 symlink 路径已经验证，但实际 symlink 门禁保持未通过；获得明确系统权限变更授权后才能重跑该单项。

## 回滚

S1 仅新增纯校验代码、测试和 Test 内实验室记录，未接入活动数据库或真实写入口。失败时可 revert 对应 Git 提交；不得删除实验室现场或覆盖活动数据。

## 后续验收

- S2：固定生产工厂、保护策略、审计上下文及全部生产入口清单；
- S3：句柄级 writer、原子写、quarantine、后置验证和竞态故障注入；
- M0 门禁前：实际 symlink 用例必须执行通过，或由用户明确批准等价的系统级验证环境；
- 全程：活动数据库和 Test 外哨兵哈希保持不变。
