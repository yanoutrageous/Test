# M0—M5 安全边界

## 1. 安全目标

本规范适用于 M0—M5 全部开发、测试、数据处理、渲染、恢复、安装和 Git 操作。安全底线高于进度、便利性和功能目标。任何操作如果不能证明安全，就应失败关闭，而不是猜测后继续。

固定路径：

```text
REFERENCE_ROOT  = D:\AAA命题
PROJECT_ROOT    = D:\AAA命题\Test
COPY_ROOT       = D:\AAA命题\Test\Copy
TASK_ROOT       = D:\AAA命题\Test\Task
TMP_ROOT        = D:\AAA命题\Test\tmp
QUARANTINE_ROOT = D:\AAA命题\Test\data\quarantine
BACKUP_ROOT     = D:\AAA命题\Test\backups
AUDIT_ROOT      = D:\AAA命题\Test\logs\audit
```

- `REFERENCE_ROOT`内普通文件允许只读。
- 项目业务文件、参考资料副本、运行状态、缓存、日志和派生结果的唯一写根是`PROJECT_ROOT`。
- `PROJECT_ROOT`之外的业务文件和参考原件均视为只读；唯一例外是第 8 节定义的、经独立审计批准的依赖包管理器事务。该例外只允许安装工具自身，不扩大项目数据写入边界。
- 系统程序和已安装运行时可按确定路径读取，但不得以“工具发现”为由扫描无关用户目录。

## 2. 永久禁止项

以下操作不能因赶进度、测试失败、恢复失败或磁盘不足而执行：

1. 在 Test 外创建、修改、移动、重命名或删除业务文件、参考资料或项目派生内容；第 8 节批准的依赖安装事务不属于业务文件写入；
2. 把处理结果写回 Test 外原件位置；
3. 对未逐项登记的目录执行递归、通配符、镜像或清空操作；
4. 格式化磁盘、修改分区、卷、引导或文件系统；
5. 提权取得目录所有权、递归修改 ACL、关闭安全软件；
6. 上传原卷、题库、成绩、备份、字体或客户数据；
7. 下载脚本后直接交给 PowerShell、`cmd`、`eval/exec`等执行；
8. 为通过测试而关闭安全检查、删除失败样本、重置金标或降低门槛；
9. 路径归属不明时继续写入；
10. 直接操作`.git`内部文件、重写 Git 历史或删除远端引用。

自动化任务不得调用或构造以下命令族：

```text
Remove-Item -Recurse -Force
rm -rf
del /s
rd /s /q
rmdir /s
robocopy /MIR
robocopy /PURGE
git reset --hard
git clean -fd / -fdx
git checkout -- .
git push --force / --force-with-lease
git push --mirror
git push --delete
git reflog expire
git gc --prune=now
Format-Volume
Clear-Disk
Initialize-Disk
Remove-Partition
diskpart
format
takeown /R
递归 ACL 重置或授予
```

即使目标看似位于 Test 内，也不得使用上述宽范围命令。删除和清理由专用安全 API 按 manifest 逐项处理。

## 3. 永久保护目录

以下目录不得被任何自动清理功能触碰：

- `Base`；
- `Copy/source`；
- `Task`；
- `backups`；
- `data/originals`；
- `data/exports`中的已发布快照；
- `logs/audit`；
- `.git`。

`PROJECT_ROOT`本身、其任何祖先目录及盘符根永远不能成为移动、删除、替换或清理目标。

## 4. WorkspaceGuard 强制规范

所有应用代码、CLI、脚本、迁移、测试工具、外部进程包装器和清理器必须共用一个`WorkspaceGuard`，不得各自拼接路径后直接写盘。

### 4.1 写路径判定

每次创建、写入、替换、复制目标、移动或删除前必须：

1. 拒绝空路径、隐式当前目录、未展开变量和盘符相对路径，如`D:foo`；
2. 拒绝其他盘符、UNC、网络共享、`\\?\`、`\\.\`和设备路径；
3. 拒绝`..`、NTFS ADS、控制字符、尾随空格/点及 Windows 保留名；
4. 对现存路径解析真实路径；新路径解析最近的现存父目录；
5. 使用组件级、大小写不敏感比较确认目标严格位于 Test 内，必须拒绝`Test2`前缀混淆；
6. 逐层检查从项目根到目标父目录，不得包含符号链接、Junction、挂载点或其他 Reparse Point；
7. 创建父目录后、正式写入前再次校验，写入后再核对最终文件，降低路径替换竞态；
8. 记录请求路径、规范化路径、用途、job ID、调用者和结果。

安全判断失败时不得尝试“自动修正路径”。

### 4.2 外部读取

读取 Test 外参考资料时：

- 不跟随 Reparse Point；
- 不递归进入链接目标；
- 只读代码不得以写模式打开；
- 可能生成锁文件、缩略图、缓存、自动保存或 sidecar 的工具不得直接接触外部原件。

### 4.3 必测攻击矩阵

M0 必须覆盖：

- `Test2`前缀混淆、大小写和 Unicode 变体；
- `..`与混合分隔符穿越；
- UNC、设备路径、其他盘符和盘符相对路径；
- ADS、尾随点/空格、保留设备名；
- 项目内 Junction/符号链接指向项目外；
- 不存在的目标但父目录为 Reparse Point；
- 校验后父目录被替换；
- ZIP/备份包中的绝对路径、链接和 Zip Slip；
- 所有`db_path`、`output_path`、`project_root`和外部程序输出参数；
- 中文长路径和合法项目内路径正常通过。

任一越界用例未被拒绝，禁止处理真实数据。

## 5. Test 外资料 Copy 流程

纯只读查看普通文件可直接进行。一旦需要转换、OCR、裁切、渲染、Office/PDF 工具打开、字体分析或其他可能产生副作用的处理，必须：

1. 只读记录外部源绝对路径、大小、修改时间、SHA-256、类型和用途；
2. 生成唯一`copy_id`；
3. 复制到`Copy/source/<copy_id>/`，目标必须不存在，禁止覆盖；
4. 复制后复算 SHA-256，必须与源一致；
5. 在追加式台账记录 source、copy、哈希、大小、时间、阶段、job 和用途；
6. 将`Copy/source`副本视为不可变项目原件；
7. 后续加工只写`Copy/work/<classification>/<copy_id>/<job_id>/`或正式派生目录，其中`classification`必须是`INTERNAL`或`RESTRICTED`且与上下文完全一致；
8. 若外部源在复制过程中变化，废弃该批次并创建新 copy，不猜测版本。

第三方工具无法证明不会写入源文件旁时，禁止直接以 Test 外路径作为输入。

## 6. 安全写入、移动和删除

### 6.1 写入

- 关键文件先写同目录唯一`.partial`文件，完成校验、刷新后再做同卷原子替换；
- 不直接截断活动数据库、manifest、运行状态或正式模板；
- 修改现有文件前记录原哈希和 Git 状态；
- 用户已有修改属于用户内容，只做增量修改；
- 数据库使用事务，迁移先在副本和 staging 上演练；
- 正式导出、模板、迁移和备份均创建新版本，不覆盖旧版本。

### 6.2 业务删除

业务内容默认不硬删除：

```text
原位置
→ Guard 校验
→ 记录哈希和引用
→ 原子移动到 data/quarantine/<classification>/<date>/<event_id>
→ 更新引用
→ 验证系统
```

M0—M5 自动运行期间不得永久清空隔离区。释放隔离区空间必须另列高风险事项并请求用户批准。

### 6.3 临时清理

只有同时满足以下条件，才可逐项清理`tmp/jobs/<classification>/<job_id>`文件：

- 目录由当前系统创建并含匹配 job ID 的安全标记；
- 真实路径位于`TMP_ROOT/jobs`且至少深入两级；
- 路径链无 Reparse Point；
- 待清理文件全部存在于本作业 manifest；
- 文件数和字节数不超过声明预算；
- 不包含永久保护目录或指向它们的链接；
- 作业已完成或已安全终止；
- 审计日志写入成功。

禁止跨 shell 枚举并删除；由单一语言的安全文件 API 在同一进程中逐项执行。

## 7. 外部进程

调用 TeX、PDF、OCR、Office、字体、图形和模型工具时必须：

- 使用允许列表中的绝对可执行文件路径和参数数组；
- 禁止`Invoke-Expression`、`eval`和`shell=True`；
- `cwd`固定在`tmp/jobs/<classification>/<job_id>`；
- `TEMP`、`TMP`、HOME、模型缓存、字体缓存和用户配置尽量重定向到作业目录；
- 设置超时、最大输出、资源上限和进程树清理；
- 不让第三方程序直接处理 Test 外原件；
- 禁用宏、插件自动下载、遥测和网络；
- TeX 禁止 shell escape/`write18`并限制输入输出根；
- SVG 拒绝脚本、外链、事件处理器、`foreignObject`和项目外引用；
- 解压逐项校验路径、数量、大小、压缩比和嵌套深度；
- 进程退出后扫描额外输出并重新通过 Guard 校验。

不得终止、修改或清理与当前 job 无关的系统或用户进程。

## 8. 依赖安装例外

默认不得安装新组件。用户本轮明确授权安装必要组件，并允许以后仅在审计证明“不安装将阻断已批准目标”时安装。

这是“项目文件唯一写根”的窄例外，不是通用的 Test 外写权限。只有官方包管理器/安装器进程可以写入审计清单中的程序、包缓存、用户 PATH 登记或卸载元数据；项目代码、脚本和人工命令仍不得借机在 Test 外创建或改写任何文件。安装前后的系统写入必须与包管理器 manifest 对账，出现额外位置立即停止并按安全事故处理。

优先顺序：

1. 使用仓库已有依赖；
2. 使用已安装的可信运行时；
3. 安装到 Test 内的虚拟环境或`tools`目录；
4. 仅当前三项均不可行且确实阻断目标时，采用用户范围、官方来源、可回滚的系统包。

每次安装前必须记录：

- 被阻塞的批准需求；
- 现有替代方案及为何不可用；
- 官方来源、精确版本、哈希和许可；
- 预计写入位置、网络访问和磁盘需求；
- 是否需要管理员权限、服务、驱动、注册表或文件关联；
- 卸载与回滚方法；
- 安装后验证和离线可复现方案。

无需提权、官方来源、用户范围、写入位置可界定且审计证明必要的工具可按 R2 执行。需要 UAC/管理员权限、驱动、服务、Shell 扩展、安全策略变化、未知来源、许可不清或无法界定安装器写入时按 R3 暂停，请求用户决定。

本轮已安装 GitHub CLI 2.96.0；这是用于阶段 push/PR 的一次性必要发布组件，记录见`CURRENT_STATUS.md`。

## 9. 单写者与并发

多代理可并行只读审查、设计和测试分析，但共享工作区同一时间只能有一个写入者。

- 写入前获取`Task/state/writer.lock`，记录 job、进程、阶段、时间和精确范围；
- 其他代理发现有效写锁后只能只读；
- 不得删除锁文件抢占写权限；
- 锁疑似过期时先审计进程和 Git 状态；
- Git、数据库迁移、正式发布和恢复切换必须独占；
- R2 高风险变更的独立审计者不得与执行者为同一角色。

## 10. 高风险操作协议

数据库迁移、正式模板激活、视觉基线更新、批量资产生成、业务隔离、恢复切换、依赖安装和 Git push 均至少按 R2 管理：

1. 冻结其他写入并获取写锁；
2. 精确列出读写移动路径、文件数和字节预算；
3. Guard、Reparse Point、隐私、磁盘和依赖检查；
4. 创建数据库一致快照和文件恢复 manifest；
5. 在 staging 干跑；
6. 独立只读审计范围、命令、恢复和验收；
7. 只执行已审计 manifest，出现额外路径立即停止；
8. 检查文件哈希、数据库完整性、测试和真实用户流程；
9. 通过后原子发布，失败则保留现场并回滚活动指针；
10. 写审计、Git 和恢复记录。

## 11. 硬停止条件

出现以下任一情况，立即停止相关写入：

- 路径不能证明位于 Test；
- 发现 Reparse Point、Junction、符号链接、ADS、UNC 或设备路径；
- 实际写入与 manifest 不一致；
- 检查点、备份、恢复或数据库完整性失败；
- 磁盘不能同时容纳旧版、候选版和恢复点；
- 活动数据疑似损坏；
- 出现任何项目/运行时 Test 外写入，或依赖安装出现审计 manifest 之外的系统写入；
- 需要上传业务资料；
- 需要管理员权限或不可审计的系统改动；
- 需要重写 Git 历史、强推或删除远端；
- 字体、原卷或交付许可影响客户交付且无法确认；
- 安全测试失败或独立审计未通过；
- 真实用户流程与测试结论冲突。

停止时保留证据，可继续不依赖该事项的安全工作；不得反复碰撞同一危险操作。

## 12. 安全事故响应

1. 停止所有相关写入和外部进程；
2. 不清理、不覆盖日志、不“现场修复”；
3. 保存命令、进程、时间、Git、路径、哈希和影响范围；
4. 在 Test 内创建只读事故快照；
5. 判断是否可能影响 Test 外；
6. 如可能越界，立即通知用户，不自行修复外部内容；
7. Test 内恢复只能从已验证检查点恢复到 staging；
8. 根因分析和安全回归通过前不得恢复自动化。

## 13. 阶段安全证明

每个里程碑必须提交：

- 全部写路径清单；
- 项目/运行时 Test 外写入数量（必须为 0）；
- 经批准的依赖安装系统写入清单及其包管理器对账结果（与项目写入分开统计）；
- Copy 台账与外部源前后哈希；
- R2/R3 审计清单；
- 隔离区和临时清理清单；
- 数据库完整性与恢复结果；
- WorkspaceGuard 攻击矩阵；
- Git 暂存、隐私和远端推送记录；
- 独立安全审计结论。
