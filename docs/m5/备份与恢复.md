# 备份与恢复

在首页进入“备份与恢复”。

1. 创建全量备份，查看文件数、逻辑大小、实际存储和验证结果。
2. 后续可选增量备份；未变化文件通过内容寻址复用，不重复占用空间。
3. 恢复时选择一个状态 ID。系统先恢复到 staging，并检查文件哈希、SQLite 完整性、
   外键、M1/M2/M3 manifest 和固定用户流程。
4. staging 通过后仍不会自动切换。显式激活前系统会先创建救援备份。
5. 切换失败会回到原活动状态；需要时可使用“回滚”返回 predecessor。
6. 激活或回滚后重启应用，再执行搜索、组卷和五类文档检查。

全量备份包含已导入 PDF 的受控 `Copy/source` 副本、`data/imports` 页面资产、题库数据库及
人工复核状态。恢复后这些内容与代表卷数据一起验证；不要只复制 SQLite 文件。

当前备份与活动产品位于同一卷，因此只能防误删、逻辑损坏和应用级恢复，不能防整个磁盘损坏。
如需异盘灾备，应在服务完全停止后，由用户把整个产品根复制到另一个受控 NTFS 卷；
当前自动化没有获得写入其他盘的授权。

不要手工拼接不同日期的数据库、assets、模板和 manifest，也不要直接编辑
`data\db\active-state.json`。

迁移电脑时应在服务停止后复制整个发布目录。路径、活动状态和 manifest 都使用产品根相对
路径，不绑定原电脑的盘符或用户名；新电脑仍需放在普通本地 NTFS 目录中。
